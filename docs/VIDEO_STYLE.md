# 视频视觉规范

## 目标

Scene Gen 的竖屏视频以“先看懂，再看动效”为原则：第一帧就能识别主题，旁白出现时对应证据已经在画面中，装饰不抢正文，所有关键文字都在安全区内。

## 设计来源

本规范借鉴 [HyperFrames](https://github.com/heygen-com/hyperframes) 的 frame-first 思路，但不引入其运行时或代码。项目继续使用原有的 HTML、Playwright 和 FFmpeg 渲染链，保留本地可运行、可缓存和可回归的确定性。

借鉴的原则包括：

- 先定义 frame design tokens，再编写每个场景的布局。
- 用一个主色建立视觉识别，使用色阶区分层级，不堆叠霓虹色和渐变。
- 用边框、留白和轻微偏移制造层次，避免重阴影和全黑画布。
- 标题、证据、结论按信息层级排版；卡片不是默认网格，而是服务于内容结构。
- 动效使用短时进入、可预测的强调和进度变化，不能把关键内容推迟到旁白之后。

## 当前实现

- `src/templates/frame-design.ts` 是共享 token 和 CSS 的唯一入口。
- `commonHtml()` 为每个 HTML 场景提供浅色画布、统一页眉页脚、主色、卡片表面和安全区。
- `data-sg-design` 记录当前视觉版本；视觉缓存会随 renderer version 变化自动失效。
- `inspectSceneDom()` 强制检查视觉版本、首帧页眉页脚、对比度、字号、越界、裁切、遮挡和动画停留。

## 场景规则

### 标题页

- 只保留一个核心结论，不重复完整标题或加入空泛开场。
- 标题使用最大字号，副标题只补充一个结果或限制。
- 日期、Star 数和来源标签是证据，不得与标题争夺视觉焦点。

### 证据页

- 一屏只表达一个结论。
- 数据卡最多三到四个；长文本优先拆成结论和证据两层。
- 图片、截图和流程节点必须有明确用途，不能为了填空白而添加。

### 结尾页

- 给出选择建议、限制或下一步，不重复标题。
- 结论出现后保留足够时间，不用新的装饰覆盖它。

## 禁止项

- 不使用全黑或近黑根画布。
- 不把网站地址、二维码、广告或站外引导放入成片。
- 不让装饰文字伪装成事实、指标或产品功能。
- 不用固定五屏代替内容规划，也不为追求动效连续切换页面。
- 不使用未经过字号、对比度和溢出检查的模板。
